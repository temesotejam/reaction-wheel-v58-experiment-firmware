研究は、動的βで姿勢を観測し、必要な電流積分量Qを選んで歩行用周期運動を作るところまで進んでいます。V7 Run 2では動画基準で±8度付近の周期運動を確認しました。現在の中心課題は、この動作を初期状態・電池・方向などが変わっても再現するために、モーター入力と実際の応答の関係を調べることです。

V58はそのためのPROBE/COAST測定版です。ソフト実装とビルドは完了しています。保存された `FLASH_RESULT.json` は `WAITING_FOR_USER_USB_RECONNECTION`、`flashed=false`、`measurement_started=false` です。最後に記録上実機へ入っている版はV57bですが、今回実機へ接続して確認した情報ではありません。

## 3. 動的βについて、確定したことと残る区別

2026-08-17の150 mA・40 ms比較では、動画白線を外部基準とし、同じIMU入力から固定β=0.100、β=0、保持73/120/170 ms、turnfastを比較しました。Run 4の代表RMSEは固定0.100が1.132度、保持170 msが0.474度、turnfastが0.462度でした。

これにより、入力時の加速度外乱を避ける動的βの基本方式を、以後の姿勢観測に使う判断になっています。ただし最小RMSEの系列名と、後続ファームが採用している系列は同じとは限りません。現コードの採用参照はHOLD_073で、turnfastと保持170 msをそのまま採用へ置き換えてはいません。

V58ではさらに、測定用固定パルス状態が歩行用β切替フラグへ接続されていないため、採用系列は通常β=0.025で更新されます。この点は2026-09-19のソース確認に基づく説明で、今回新たな姿勢推定性能を測ったという意味ではありません。詳しくは [動作解説 第3〜5節](OPERATION_GUIDE_JA.html)。

## 4. V7で確認した歩行用周期運動

V7 Run 2の動画とRWLOGをLEDで同期し、70/70ピークを同じ半周期の動画極値へ対応付けています。定常域は62ピークで、動画の＋側/−側中央値は+8.030/−8.221度、中心補正振幅8.126度、8度目標に対するMAEは0.220度でした。LED時刻対応のMAEは10.010 msです。

この結果を、姿勢推定・自然減衰・必要Q計算・ゼロ交差出力を統合して周期運動が成立した根拠としています。ここで直接評価したのは左右の周期運動と振幅制御です。移動距離、歩行速度、連続歩数、床条件を変えた再現性まで定量化したデータではありません。

原本識別: canonical V7 Run 2 `20260904_135926_062_aef5`。図と根拠は [歩行までの進捗PDF](../references/2026-09-15_dynamic_beta_to_walking_report_ja.pdf) の第5節を参照してください。

## 5. V46〜V53で、Qを実際に届ける問題を分解した

実測Qで停止するには、電流をいつ読んだか、どの区間を積分したか、ゼロ指令がいつ完了したかを確認する必要があります。V46〜V49では処理負荷と電流gapを、V50では観測Qの端点を、V51では実測Q停止を、V52ではhard deadlineを実装し、V53では到達精度を監査しました。

V52の2 Runでは通常137パルス、100 ms超過0、最大99.073 ms、Q到達116件・hard停止21件でした。ただし最大6.8814 mA·sの不足例が残りました。期限を守れたことと必要Qが毎回届くことは別の確認です。

例えばRun 2のpulse 7は目標10.248に対して判定Q10.365 mA·sでQ到達停止、pulse 59は目標13.475に対して6.593 mA·sで期限停止です。このような差を、停止遅延だけでなく入力前の車輪状態も含めて調べる段階へ進みました。

波形は [実測時系列PDF](../references/2026-09-15_current_status_timeseries_ja.pdf) にあります。V52の性能を、そのまま未測定のV58の性能として転記していません。

## 6. V54〜V57bで、比較できる初期状態を作った

V54ではパルス直前の車輪速度を観測しました。V55以降は初期速度を意図的に変えて固定パルスを比較する専用測定へ進みましたが、速度準備の成立やモード切替の順序、準備後に電流が落ち着くまでの窓が課題になりました。

V56系ではSpeed ModeからCurrent Modeへ順番に切り替える処理を整え、V56cでは短い速度差分の量子化ゆらぎを避けるため、100 ms以上離れた点で速度傾きを判定しました。V57では固定パルス測定を整え、metadata、保存容量、停止境界の扱いを修正しました。

V57bは毎試行の独立baselineと、`|I−baseline|≤max(3 MAD,0.2 mA)` が30 ms続く移行判定を導入し、Qの比較窓を開始後0〜50 msへ揃えました。結果として、以前の誤ESTOPが再発しない3 Runを得ています。

## 8. そのためにV58で何を追加したか

同じ300 mAパルスの結果だけを見ると、初期速度による自然減速と、モーターが生んだ変化を分離できません。そこでV58は、同じ準備・移行を行った後、0 mAのまま観測するCOASTを対照として追加しました。

開始前と10/20/30/40/50 msの速度を実時刻付きで記録し、Q50は開始0〜50 msで再計算します。同Run・方向・領域内で初期速度、残留電流、Vbus、速度観測dtが近いPROBE/COASTを一対一対応し、その速度変化差を調べます。もう一つの方法としてCOASTの速度変化率を回帰し、差引き結果を比較します。

ここでいうCOASTは通電したドライバのCurrent Mode 0 mAであり、完全な無通電自由回転と同一ではありません。また、差引き後の速度変化/Qを純粋なトルク定数とは扱いません。V58は原因を切り分けるための測定設計で、自然減速が原因だとすでに実証した結果ではありません。

## 10. 再開時に何を行うか

1. USB再接続後、対象個体・ポートを確認してV58を書き込む。過去のCOM7を無条件に現在のポートとみなさない。
2. 書込みhash、通常起動、Wi-Fi、画面revisionを確認する。最後に確認したV57bへ戻せる元プロジェクトは保持されている。
3. 固定した機体で必要な開始確認を行い、V58 Fullを2 Run以上取得する。条件不足の場合もRWLOGを保存する。
4. CRC、電流gap、停止期限、50 ms速度点、条件別有効数、マッチ成立数を監査する。予定pair_idだけで同条件と判断しない。
5. PROBE差分、COAST差分、差引き差分とQ50の関係を、方向・初期状態・Runで比較する。paired法と回帰法の不一致も確認する。
6. 支持される範囲が得られたら入力モデルを検討し、別の歩行用派生版で反映・検証する。V58測定版をそのまま歩行成功版とみなさない。

今回の依頼は解説付きZIPの作成であり、この再開手順の実機操作は実行していません。
